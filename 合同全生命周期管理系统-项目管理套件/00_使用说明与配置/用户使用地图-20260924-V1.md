```
        ┌─────────────────────────────────────────────┐
        │  ① 业务台账（人工录入，唯一事实源）            │
        │  01–10 各领域工作簿 · 黄色字段人工维护          │
        └──────────────┬──────────────────────────────┘
                       │ 更新后
                       ▼
        ┌─────────────────────────────────────────────┐

                       ▼
        ┌─────────────────────────────────────────────┐
```

## 四、场景路线（按"我来干什么"）

### 路线 1：我只想看项目状态
打开 `11_AI_PMO中心/AI PMO中心-当前版.xlsx` → 项目驾驶舱（KPI 与红黄项）→ AI项目诊断。不需要跑任何命令。

### 路线 2：我更新了某个台账，要让驾驶舱跟上
1. 确认新版本已登记进 `current_workbooks.json`；
2. `python3 scripts/sync_all_to_ai_pmo.py --date YYYY-MM-DD`（预览）；
3. 确认输出无误后加 `--apply`（自动备份到 `_archive/自动刷新前备份/`）。

### 路线 3：我改了人工成本或预算
1. 成本簿内改数（人工成本预算 / 预算基线 / 月度投入明细）；
2. `python3 scripts/sync_cost_all.py`（预览）→ `--apply`。一次完成：驾驶舱成本四项（人天/成本/单价/**已量化总预算**）+ G15 三份材料口径。
> 只动接口执行状态时改走 `sync_scope_to_integration.py`（03↔04 双向，预览→`--apply`）。

### 路线 4：我要发周报
1. 当天先跑 `./run.sh agents --date YYYY-MM-DD`（只读分析，生成 Agent 结果簿）；
2. 项目经理在结果簿黄色列填确认结论 → `./run.sh review-import --file … --reviewer 项目经理`；
3. `./run.sh weekly-report --date YYYY-MM-DD` → 产出在 `08_沟通会议与报告/周报/`（Excel 分析版 + Word 汇报版）。

### 路线 5：我要准备上会材料（POC 选型 / 预算 / G15）
1. 更新证据台账（评分表、报价对比、会签清单——均为人工签认）；
2. `./run.sh decision-brief --date YYYY-MM-DD` 生成简报草稿；
3. G15 材料跑 `sync_cost_all.py --apply` 统一口径；
4. **简报是分析材料，审批结论由委员会签署，程序不代批。**

### 路线 6：我想检查数据有没有打架（只读，安全）
- 每日全巡检：`python3 scripts/run_daily_pmo.py --date YYYY-MM-DD`
- 接口/资源关联：`PYTHONPATH=src python3 scripts/audit_data_links.py`
- 跨簿联动：`PYTHONPATH=src python3 scripts/audit_portfolio_links.py`
- 迁移门禁：`python3 scripts/audit_migration_gates.py --gate … --plan …`（六本显式指定）
- 主源归属：`python3 scripts/audit_source_ownership.py --suite ..`
以上全部只读，可放心随时跑。

## 六、命令速查（写入类一律：先预览 → 再 `--apply`）

| 命令 | 写什么 | 频率 |
|---|---|---|
| `sync_all_to_ai_pmo.py` | 驾驶舱与数据接口（进度/门禁/风险/决策/里程碑） | 台账变更后 |
| `sync_cost_all.py` | 驾驶舱成本四项 + G15 三材料（推荐统一入口） | 成本变更后 |
| `sync_cost_to_ai_pmo.py` / `sync_cost_caliber_to_g15.py` | 上者的单段独立版 | 按需 |
| `sync_scope_to_integration.py` | 03↔04 接口快照双向 | 03/04 变更后 |
| `./run.sh agents` | Agent 结果簿 + JSON + 数据库记录 | 周报前 |
| `./run.sh review-import` / `review-summary` | 人工确认结论入库 | Agent 后 |
| `./run.sh weekly-report` | 08 周报 Excel+Word | 每周 |
| `./run.sh decision-brief` | 08 POC 决策简报 | 上会前 |
| `run_daily_pmo.py` | 不写业务簿；`--generate-derived` 也只产派生件 | 每日 |

**不要日常使用的命令**：`build` / `run`（会生成当日 V1 新簿，遇同名即停，不是刷新命令）。

## 七、红线（所有人必读）

1. **颜色纪律**：黄色=人工录；灰色=自动算（勿改）；蓝色=程序关联生成；红色=校验失败待处理。
2. **审批边界**：基线、预算批准（D-003）、风险等级、问题关闭、变更批准、采购选型、对外发布——只能由授权人确认，程序只出建议和待审材料。
3. **唯一事实源**：每个业务对象只有一个录入表（见 `config/data_ownership.json`）；驾驶舱、数据库、周报均为派生。
4. **版本纪律**：新簿发布先登记 `current_workbooks.json`；禁止按文件修改时间选最新版。
5. **同步纪律**：所有写入命令默认预览；`--apply` 前自动备份，但备份不代表人工修改能自动合并——刷新前先看预览输出。
6. **归档纪律**：`_archive/` 仅供追溯，不得当作当前基线引用。
