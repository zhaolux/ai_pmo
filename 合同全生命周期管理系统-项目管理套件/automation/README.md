# 能源行业合同管理 AI PMO

本项目以能源行业合同全生命周期管理系统为案例，用 Python 统一管理中央数据，并按项目目录生成和更新 Excel 管理文件。

## 设计原则

- `90_项目数据中心/ai_pmo.db` 保存初始基线、输入索引和运行记录；当前业务事实仍需核对领域台账与人工确认记录，不能将数据库或 Agent 报告单独视为审批后的业务主源。
- 各业务目录中的 Excel 承担录入、分析和汇报；跨工作簿联动主要使用 Python 快照同步，不使用跨工作簿公式。
- 业务对象通过 `Project_ID`、`Task_ID`、`Person_ID`、`Risk_ID` 等唯一编号关联。
- V2 模板提供既有表格结构和视觉规范，PMBOK 第8版学习文档提供治理和检查框架。
- 每次运行保留日志和数据快照，生成过程可重复执行。

## 运行

使用项目自带启动脚本，无需先安装为系统包：

```bash
./run.sh init
./run.sh scan
./run.sh validate
./run.sh build
./run.sh run
```

`run` 会依次执行初始化、扫描、校验和模块文件生成。

注意：`build` 和 `run` 会生成当天的模块 `V1` 工作簿；现在会先检查全部目标，只要有同名文件就停止，不提供强制覆盖参数。它们不是正式台账的日常刷新命令。各命令的数据来源、写入位置和覆盖风险见 [数据血缘与写入边界](docs/DATA_LINEAGE_AND_WRITE_POLICY.md)。

日常项目检查统一使用以下入口：

```bash
python3 scripts/run_daily_pmo.py --date 2026-09-22
```

默认模式先核对十二类当前工作簿登记和项目工时/单价参数，再执行数据主源审计、接口/资源数据联动审计、接口快照同步预览、项目组合联动审计、AI PMO全量刷新预览、成本刷新预览、Agent输出目标预览和周报输出目标预览。任一步失败立即停止；默认不写业务工作簿、不生成派生报告、不写运行数据库。需要生成当天 Agent 分析和周报时显式执行 `python3 scripts/run_daily_pmo.py --date 2026-09-22 --generate-derived`；该模式仍不执行两项 AI PMO 原位刷新，也不改变任务、风险、预算、门禁或审批结论。同日期派生文件已存在时会按原命令规则停止，不自动覆盖。

`config/data_ownership.json`登记相关方、里程碑、任务、资源、预算、风险、问题、变更、决策、测试、缺陷、UAT、交付物、行动项和迁移来源的唯一录入表、表头行及主键。只读命令`python3 scripts/audit_source_ownership.py --suite ..`会检查重复主源、登记工作簿、Sheet、主键表头和重复ID；同一Sheet存在多个表格时用`data_start_row`和`data_end_row`限定主数据区域。派生报表不在此处登记为业务主源。

AI PMO 采用“跨工作簿快照 + 工作簿内部公式”联动，避免 Excel 外部链接丢失。上游台账更新后执行：

```bash
python3 scripts/sync_all_to_ai_pmo.py --date 2026-09-18
```

该命令会读取当前计划、启动治理和风险/变更工作簿，同步任务进度、延期、两周到期、里程碑、门禁、风险、决策和相关方指标。成本指标由独立的 `scripts/sync_cost_to_ai_pmo.py` 同步，不包含在本命令中。全量同步对生成命令实施目标区域白名单，禁止写入诊断表中的人工状态、建议和责任人单元格。

默认运行只列出数据日期、实际选中的源文件、目标工作簿和拟更新区域，不修改 Excel。确认后显式添加 `--apply` 执行，例如：

```bash
python3 scripts/sync_all_to_ai_pmo.py --date 2026-09-18 --apply
```

执行前会核对“两周督办”L:M 的人工填值是否仍对应同行任务 ID；若任务排序或清单缩短导致错配，停止刷新，须先由责任人按任务 ID 整理人工内容。正常刷新会清除已退出清单的 A:K 自动生成旧行，但不会自动清空或迁移 L:M。执行时会在目标工作簿同目录的 `_archive/自动刷新前备份/` 留下校验过的原文件副本；日志新增行必须在 A:J 范围内完全空白，含人工文字或公式的行不会被占用。下列刷新效果仅在 `--apply` 成功执行后产生：

- 重建“数据质量检查”，检查模块文件、模块编号、重复任务ID、非法状态、负责人、计划日期和逾期任务证据；
- 在“AI运行日志”追加一条运行记录，保留运行ID、时间、范围、发现、风险等级和待确认结论；
- 保留人工填写的日志历史，不覆盖已经确认的结论。

`--date` 为统计截止日期，正式发布周报时应显式指定。

仅刷新成本指标时，先预览实际选中的成本源文件、AI PMO 目标和拟写入的 9 个单元格：

```bash
python3 scripts/sync_cost_to_ai_pmo.py
```

确认后执行 `python3 scripts/sync_cost_to_ai_pmo.py --apply`。脚本读取“人工成本预算”的总人天和总成本，计算平均人日单价；执行前会在 AI PMO 目标同目录的 `_archive/自动刷新前备份/` 保存校验过的原文件副本。成本刷新仅写“项目驾驶舱”B9:D9 与“_数据接口”B16:B21，不修改成本源台账。

成本口径数字（计划人天/人工成本/平均人日单价）还需联动到 G15 会前材料（签认跟踪表 SIG-02 口径句与两份 G15 md）时：

```bash
python3 scripts/sync_cost_caliber_to_g15.py
```

确认后执行 `python3 scripts/sync_cost_caliber_to_g15.py --apply`。脚本按文件名模式定位最新的 `G15-会前签认跟踪-*.xlsx`、`G15-未决事项处置建议包-*.md`、`G15-会前材料包清单与缺口对照-*.md`，把人天/万元/单价三连、人工成本万元数、签认引述和驾驶舱口径行的数字改写为当前成本口径（xlsx 走 zipfile 级字符串替换，不动公式缓存）。默认仅预览命中处数；`--apply` 执行前备份各目标到 `_archive/自动刷新前备份/`。改写为相同值时幂等，可重复执行。日常巡检第 7 步以预览方式运行本命令。

两段联动（驾驶舱 + G15）也可一次完成，推荐日常使用统一入口：

```bash
python3 scripts/sync_cost_all.py
```

确认后执行 `python3 scripts/sync_cost_all.py --apply`。先跑驾驶舱同步（officecli 白名单写入，备份 AI PMO 工作簿），再跑 G15 口径联动（备份各目标）；两段都带预览后目标防切换守卫，第一段失败即停、第二段不执行。`sync_cost_to_ai_pmo.py` 与 `sync_cost_caliber_to_g15.py` 仍可单独使用。

03 需求与范围管理与 04 系统集成管理的接口快照支持按列归属双向同步：

```bash
python3 scripts/sync_scope_to_integration.py
```

确认后执行 `python3 scripts/sync_scope_to_integration.py --apply`。同步口径：接口清单和 P0 规格的范围字段（清单ID、系统、名称、描述、方向、范围决策、优先级、责任人、规格定义等）以 03 为权威写入 04；执行字段（规格状态、测试状态、备注）以 04 为权威写回 03。03 新增的接口/规格自动追加到 04；04 出现 03 没有的记录视为结构错误，不删除不写入，命令退出码为 1。默认仅预览差异；`--apply` 执行前分别备份两本工作簿到各自目录 `_archive/自动刷新前备份/`，写入后自动复核，残留差异会使命令失败。编辑 03 范围或 04 执行状态后运行本命令，再跑 `audit_data_links.py` 确认无漂移。

风险管理已拆分为两个工作簿：`风险管理-日期-版本.xlsx`维护风险识别、评估和应对；`问题与变更管理-日期-版本.xlsx`维护问题、变更和待决策事项。两个文件仍位于`06_风险问题与变更`目录，刷新程序按文件名前缀分别读取，不能随意修改前缀。

当前源文件和 AI PMO 目标文件由 `config/current_workbooks.json` 显式登记。新增正式版本后，先由项目负责人核对文件和审批状态，再把对应条目改为套件根目录下的相对路径。全量同步、成本同步、Agent 和决策简报会读取登记版本；登记缺失、文件不存在、目录或前缀不符、指向归档时停止，不回退到修改时间最新的文件。`--preview-targets` 仅预览生成文件，不替代登记文件的输入核对。数据质量检查仍会扫描模块目录中的工作簿结构，用于发现并列文件的问题；这些文件不因此成为业务指标的源文件。

检查需求范围、系统集成和计划资源之间的关键关联，可运行只读命令：

```bash
PYTHONPATH=src python3 scripts/audit_data_links.py
```

该命令读取登记的 `scope`、`integration`、`plan` 当前版本，核对接口清单与 P0 规格的逐字段快照、实施任务关联的清单/规格/总控 ID，以及人员周任务清单中的总控任务 ID。输出 JSON；错误使退出码为 1，未分配资源的总控任务列为警告。命令不写业务工作簿，不自动同步接口快照或生成资源承诺，也不覆盖成本、风险、质量等其他领域的验收。

旧合同系统迁移门禁可用 `scripts/audit_migration_gates.py` 只读核对。命令要求显式提供四本文件，避免按修改时间误选旧版；在 `automation/` 目录运行，例如：

```bash
python3 scripts/audit_migration_gates.py \
  --gate ../01_项目启动与治理/项目启动与治理-20260917-V1.xlsx \
  --plan ../02_计划与进度管理/计划与进度管理-20260918-V6.xlsx \
  --launch ../09_上线移交与运营/上线移交与运营-20260918-V5.xlsx \
  --migration ../09_上线移交与运营/旧合同系统迁移管理-20260920-V1.xlsx \
  --quality ../07_质量测试与验收/质量测试与验收-20260918-V5.xlsx \
  --risk ../06_风险问题与变更/风险管理-20260918-V1.xlsx
```

输出 JSON 列出 G15、T087/T092、MIG-001—006、RDY-005、CUT-005 的来源行、状态和计划日期，并核对演练、计划执行、生产切换的日期先后。`source_inventory` 按 SRC 线索行核对实际系统名称、独立边界、责任人、记录/附件量、抽取方式、历史保留边界、证据和盘点状态，输出缺失字段名及源行，不复制业务字段值；数值 0 不当成缺失。`fields_complete` 只表示已有线索行的必填字段齐全，不证明实际来源系统已穷尽，`confirmed_system_count` 因此仍为 `null`。提供 `--quality` 时，还按 MIG 的来源描述唯一关联“数据质量与迁移”，分别报告规则覆盖数与有结果、有完成状态、有证据的验证数；规则存在不等于验证通过。提供 `--risk` 时，额外读取 RSK-007 的责任人、应对期限、剩余等级、状态与台账所填关闭证据文本；该文本不由程序认定为已核验的证明。结构性缺失、重复 ID 或无法唯一关联使退出码为 1；待盘点、待确认、未就绪、待处理风险或未完成验证不自动视为程序错误或审批结论。MIG 的日期是计划执行日，六条来源线索不代表六套已确认系统。程序不修改工作簿，也不判定 G15、风险关闭或上线准入是否获批。

刷新会改写列出的自动计算区域；备份提供恢复依据，但并不表示任意人工修改都能自动合并回目标工作簿。

## AI PMO Agent 第二阶段

当前已提供六个协同角色：AI PMO主控、进度资源Agent、风险问题Agent、成本合同Agent、质量验收Agent和沟通报告Agent。运行：

```bash
./run.sh agents --date 2026-09-18
```

该命令只读分析最新的计划、风险、问题、变更、待决策、预算、采购包、付款、质量门禁、缺陷、UAT、验收、行动项和升级台账，一次完成三处更新：生成`outputs/agents/agent-report-YYYYMMDD.json`，将运行及发现写入中央数据库，并生成`11_AI_PMO中心/AI PMO-Agent运行结果-YYYYMMDD-V1.xlsx`。工作簿同时包含管理层摘要、重点关注事项和建议处理顺序。同一数据日期的派生文件默认拒绝覆盖；数据库保留历次运行记录。Agent不会直接修改任务状态、项目基线、预算、风险等级或审批结论。

项目健康度由`config/health_model.json`统一配置，按进度25%、成本20%、风险与问题20%、质量15%、资源10%、相关方与沟通10%加权计算。重大事项触发红色硬门槛；每次运行把总分、状态以及六个分项的权重、扣分和发现数写入`health_snapshot`与`health_dimension_snapshot`，可用于趋势分析。进度资源Agent还会检查资源计划当前周记录，将负荷率超过100%或判定为“超负荷”的人员列为高严重度事项。

项目经理可在Agent结果工作簿“发现清单”的黄色列填写确认状态和人工结论，然后导入确认记录：

```bash
./run.sh review-import --file ../11_AI_PMO中心/AI\ PMO-Agent运行结果-20260923-V1.xlsx --reviewer 项目经理
./run.sh review-summary --run-id AGENT-20260923-HHMMSS
```

导入前会一次性校验工作簿中的运行ID、发现ID、重复项和状态；“已接受、需调整、已关闭”必须填写人工结论，任一错误都会整批拒绝。确认结果只写中央数据库`agent_finding_review`，不自动改变任务、风险、预算或其他业务台账。业务事实仍须由责任人在唯一主源中更新，再重新运行Agent形成新快照。

生成面向项目例会和管理层沟通的周报：

```bash
./run.sh weekly-report --date 2026-09-18
```

运行前需已执行同日期的`agents`命令。结果写入`08_沟通会议与报告/周报/`，同时生成Excel分析版和Word汇报版。周报"成本投入概况"节（计划人天/人工成本/平均人日单价/实际投入/完成率）在生成时直读当前成本工作簿《人工成本预算》合计行与《月度投入明细》实际合计，与驾驶舱及 G15 材料同一口径；历史周报为按日快照，不追补该节。

生成 CA及电子签章、电子文档、BI报表三项外部产品的 POC 选型决策简报：

```bash
./run.sh decision-brief --date 2026-09-19
```

结果写入`08_沟通会议与报告/决策简报/`，包含供后续 AI 使用的 JSON 事实包和供项目治理委员会审阅的 Word 文档。命令只读源台账；缺少评分和报价时标为“未取得/未核验”，采购金额未填写时标为“待估算”。简报是分析材料，不代替选型、预算或采购审批。

架构、字段和权限说明见`docs/AI_PMO_AGENT_ARCHITECTURE.md`。
同日期 Agent 报告、周报和决策简报默认拒绝覆盖。确需重生成纯派生输出时，显式添加 `--replace-generated`，例如 `./run.sh agents --date 2026-09-18 --replace-generated`；该参数不适用于 `build/run`，也不代表可覆盖人工审批结论。外发前仍应核对数据截止日、证据和人工确认结论。

运行 `build`、`run`、`agents`、`weekly-report` 或 `decision-brief` 前，可添加 `--preview-targets` 查看将生成的每个文件及“将新建/已存在”状态，例如 `./run.sh agents --date 2026-09-20 --preview-targets`。预览不初始化数据库、不写日志或工作簿，也不执行源数据扫描；因此它只核对输出路径，不证明输入完整或生成一定成功。正式执行时会重新检查同名目标。

## 配置

- `config/project.json`：项目参数、工时和初始化成本规则。当前人日单价按已修订人工成本预算的“总成本/总人天”计算；正式成本指标始终以 `current_workbooks.json` 登记的成本工作簿为唯一业务来源，预算变化后应同步更新初始化参数，不能用旧的 1200 元/人日覆盖成本台账。
- `config/directories.json`：业务模块与目录映射。
- `config/sheet_mapping.json`：V2 Sheet 与业务模块映射。
- `config/status_rules.json`：任务、风险、问题、变更状态规则。
- `config/current_workbooks.json`：同步、Agent 和决策简报使用的当前工作簿登记；发布新版本后须由负责人更新。
- `config/data_ownership.json`：业务对象唯一录入入口、主键及有效数据行范围。
- `config/health_model.json`：六维健康度权重、严重度扣分、阈值和红色硬门槛。

## 人工维护边界

- 黄色字段：人工录入字段，后续同步会读取。
- 灰色字段：系统计算字段，不应人工覆盖。
- 蓝色字段：关联字段，由 Python 根据唯一编号生成。
- 红色字段：校验失败或需要处理。
