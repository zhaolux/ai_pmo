# 唯一入口联动检查落地清单

对应 ROADMAP"下一步"第 0 条：固化"唯一入口、一次录入、多处使用"。
本文档把该目标分解为**已具备基线 / 待补缺口 / 执行顺序与验收**三部分，作为逐项落地的工单。每完成一项，按"验证与交付"节登记证据并更新 ROADMAP。

## 一、目标定义

- **唯一入口**：15 类业务对象（`config/data_ownership.json` 登记的 stakeholder / milestone / task / resource / budget / risk / issue / change / decision / test_scenario / defect / uat / deliverable / action / migration_source）各只有一个录入表、一个主键；
- **一次录入**：事实在权威台账维护一次，跨簿使用全部经程序快照或活公式传导，禁止第二处人工抄录；
- **多处使用**：每个下游使用点（驾驶舱、周报、简报、G15 材料、组合审计）都有自动化检查证明"与源一致"。

## 二、已具备基线（2026-09-25 核对，勿重复建设）

| 能力 | 载体 | 覆盖 |
|---|---|---|
| 主源归属审计 | `audit_source_ownership.py` | 15 类对象重复主源、登记簿存在性、主键表头、重复 ID |
| 日常巡检编排 | `run_daily_pmo.py`（每日 09:30 定时） | 9 步：主源审计→数据联动→接口快照预览→组合审计→全量刷新预览→成本预览→G15 预览→Agent/周报预览，只读、遇错即停 |
| 接口双向联动 | `sync_scope_to_integration.py` + `audit_data_links.py` | 03↔04 接口清单/P0 规格逐字段快照；04 实施任务↔清单/总控 ID；资源周任务↔总控 ID |
| 组合联动审计 | `audit_portfolio_links.py` | 里程碑、总控任务、风险、待决策、缺陷、UAT、交付物的跨簿计数核对与驾驶舱快照一致性 |
| 迁移门禁审计 | `audit_migration_gates.py` | G15/T087/T092/MIG-001—006/RDY-005/CUT-005 来源行、日期先后、来源盘点字段齐全性、质量规则覆盖 |
| 成本联动 | `sync_cost_all.py`（驾驶舱四项指标含已量化总预算 + G15 三材料） | 预览→`--apply`→备份，幂等可重跑 |
| 版本唯一源 | `config/current_workbooks.json` 登记 | 全量/成本/Agent/简报只读登记版本，缺失或指向归档即停，不按修改时间猜 |
| 写入纪律 | 所有写入命令默认预览、`--apply` 前备份、写入白名单 | 见数据血缘与写入边界文档 |

## 三、待补缺口（按优先级排序，即执行顺序）

### P1 把迁移门禁审计纳入日常巡检

- **问题**：`audit_migration_gates.py` 要求六本文件显式传参，未编入 `run_daily_pmo.py` 九步；迁移是 G15（2026-10-13）前第一重点包，检查频率应与重点程度匹配。
- **动作**：给脚本增加 `--suite` + 从 `current_workbooks.json` 解析六本登记版本的入口（保留显式传参作备用）；在 `daily_run.py` 九步中"项目组合联动审计"之后插入第 5 步"迁移门禁审计"。
- **验收**：TDD 先写测试（夹具缺簿即该步失败、登记解析正确）；全量回归通过；真实套件跑一次 `run_daily_pmo.py` 全绿；README 命令说明与血缘文档同步。

### P2 问题/变更纳入组合审计

- **问题**：`audit_portfolio_links.py` 只核对待决策计数；问题台账、变更台账的跨簿使用点（驾驶舱、周报、Agent）没有计数核对，"多处使用"证据缺一角。
- **动作**：在组合审计中增加 issue/change 的源计数与驾驶舱/周报口径核对（口径先与现有 counts 节对齐，不新建标准）。
- **验收**：同 P1 的 TDD + 回归 + 真实运行零错误；核对值与人工台账抽验一致。

### P3 成本快照一致性纳入组合审计

- **问题**：成本有独立的同步预览（巡检第 6 步），但"驾驶舱 `_数据接口` 中的成本四项 vs 成本簿当前重算值"只在同步预览里隐式覆盖；组合审计没有显式的一致性断言，漏同步时不易发现。
- **动作**：`audit_portfolio_links.py` 增加成本节——重算成本簿合计与预算基线合计，和 `_数据接口` B17/B18/B19/B43 比对，超容差（如 ±0.5 元）报错误。
- **验收**：构造"驾驶舱滞留旧值"场景测试必败、刷新后必过；真实运行零错误。

### P4 沟通/行动项纳入检查面

- **问题**：`action` 对象已登记主源，但无任何联动检查；沟通逾期等指标驾驶舱在用（`_数据接口` B32）。
- **动作**：组合审计增加 action 源计数与驾驶舱口径核对；`audit_source_ownership.py` 已覆盖其主源唯一性，无需改动。
- **验收**：同 P2。

### P5 发布新版本登记核对单（人工环节固化）

- **问题**：`current_workbooks.json` 已是唯一源，但"发布新簿→更新登记"靠人记，漏登记时下游命令停止却无主动提醒。
- **动作**：在 `run_daily_pmo.py` 第 1 步（登记核对）中增加提示：发现目录内存在比登记版本日期更新的同前缀工作簿时，输出"疑似未登记新版本"警告（只警告不猜测、不回退）。
- **验收**：构造夹具——未登记新簿时警告出现且退出码仍为 0（警告不阻断）；已登记场景无警告；文档同步"警告不等于选版依据"的纪律。

### P6 检查项注册表（防再散）

- **问题**：检查逻辑散在 4 个 audit 脚本里，新增对象（如未来 D-xxx 证据类）无处可登记。
- **动作**：在 `data_ownership.json` 增加可选 `linkage_checks` 字段（声明该对象参与哪些审计），`audit_source_ownership.py` 校验声明的审计脚本存在；不迁移现有逻辑，只做注册与存在性校验。
- **验收**：TDD；误填脚本名报错；现有 15 对象不填字段时行为不变。

## 四、统一验收纪律（每一项都要）

1. TDD：先写失败测试再实现；跨模块改动跑 `automation/tests/` 全量；
2. 真实套件运行：相关 audit / 巡检命令对当前簿零错误；
3. 文档同步：`automation/README.md` 命令说明、血缘文档、ROADMAP"最近完成与验证"；
4. 不越审批边界：所有新增检查只读源台账，不改业务结论；检查发现的问题开成台账事项（问题/待决策），由授权人处置。

## 五、完成定义（Definition of Done）

第 0 条整体完成 = 上述 P1—P6 全部落地 + 15 类对象每一类都能回答："我的唯一入口在哪、被哪些下游使用、哪条命令证明它们一致"。届时把本文档移至"已交付"状态，ROADMAP 第 0 条改为回顾条目。
