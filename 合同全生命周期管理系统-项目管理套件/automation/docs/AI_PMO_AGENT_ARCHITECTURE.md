# AI PMO 第二阶段 Agent 架构

## 建设目标

第一阶段建立可审计、可复跑、默认只读的多 Agent 项目管理能力。系统先以确定性规则识别事实，再为后续大模型补充解释、归因和方案比较能力。

## Agent 分工

| Agent | 输入 | 主要职责 | 输出 |
| --- | --- | --- | --- |
| AI PMO主控 | 专业Agent结果 | 汇总项目健康度、统一严重度、形成运行报告与审计记录 | 项目健康度、结构化发现、审批边界 |
| 进度资源Agent | 项目总控台账 | 识别延期、未来14天到期任务及责任信息 | 进度发现、责任人、建议动作、证据 |
| 风险问题Agent | 风险登记册、问题台账、变更台账、待决策事项 | 识别重大/高风险、未关闭问题、待审批变更和待决策事项 | 风险与治理发现、建议动作、证据 |
| 成本合同Agent | 预算基线、采购包计划、付款里程碑 | 识别预算未量化、采购估算到期和付款证据缺失 | 成本与合同发现、建议动作、审批要求、证据 |
| 质量验收Agent | 质量门禁、缺陷台账、交付物、UAT验收 | 识别门禁到期、未关闭严重缺陷、交付物到期和UAT证据缺失 | 质量与验收发现、责任人、建议动作、证据 |
| 沟通报告Agent | 行动项、决策日志、升级事项 | 识别逾期行动、临期决策和待处理升级事项 | 沟通发现、需决策事项、管理层摘要、证据 |

## 统一发现模型

每项发现必须包含：`finding_id`、`agent`、`object_id`、`severity`、`title`、`detail`、`recommendation`、`owner`、`requires_approval`和`evidence`。

证据至少包含来源文件、工作表、记录ID和源行号。没有证据的内容不得作为正式PMO结论。

## 权限边界

- Agent默认只读项目源台账，仅输出建议和报告。
- 项目基线、预算、风险等级、任务状态、问题关闭和变更批准必须由项目经理或授权人确认。
- 后续接入大模型时，大模型只能扩展解释与方案，不得绕过规则检查和人工审批。

## 运行方式

```bash
./run.sh agents --date 2026-09-18
```

运行结果写入：

- `outputs/agents/agent-report-YYYYMMDD.json`：完整Agent报告；
- `11_AI_PMO中心/AI PMO-Agent运行结果-YYYYMMDD-V1.xlsx`：可视化结果、证据明细与人工确认入口；
- `90_项目数据中心/ai_pmo.db`中的`agent_run`和`agent_finding`：审计记录；
- `automation/logs/ai_pmo.jsonl`：命令级运行日志。

JSON、数据库和Excel由同一条`agents`命令连续生成，避免人工单独刷新导致的口径不一致。

## 后续扩展

本阶段已完成成本合同Agent、质量验收Agent、沟通报告Agent以及自动周报生成。执行`./run.sh weekly-report --date YYYY-MM-DD`后，系统会基于同日期Agent报告生成Excel分析版和Word汇报版，不会直接修改项目源台账。下一步可接入大模型，对已验证事实补充原因分析和情景方案。

POC选型决策简报由`./run.sh decision-brief --date YYYY-MM-DD`生成。系统按显式ID映射关联决策日志、采购包和预算项，保留文件/Sheet/ID/行号证据，将“已记录事实”与“分析假设”分开。该简报不自动评分、选定厂商或写回审批结果。
