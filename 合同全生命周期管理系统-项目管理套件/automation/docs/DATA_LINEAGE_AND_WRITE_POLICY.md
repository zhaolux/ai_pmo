# 数据血缘与写入边界

本文记录截至 2026-09-20 已从代码核对的实际行为。生成型命令已增加同名目标预检及 `--preview-targets` 只读目标清单；全量及独立成本原位同步已改为默认只预览、显式执行并先备份，人工维护字段仍需按区域继续核对。

## 数据角色

| 层级 | 文件或存储 | 当前用途 | 业务效力 |
| --- | --- | --- | --- |
| 参考输入 | `inputs/`、`automation/config/*.json` | 模板、需求、接口资料、项目参数和初始编制 | 参考或配置；变更仍需按项目基线流程确认 |
| 业务台账 | `01_` 至 `10_` 当前工作簿 | 人工录入和确认的进度、资源、风险、成本、质量、沟通等事实 | 经责任人确认后形成相应业务记录；不能仅凭文件存在推定已审批 |
| 结构化存储 | `90_项目数据中心/ai_pmo.db` | 初始基线、输入文件索引、运行日志及 Agent 发现 | 程序运行记录和结构化快照；不是全部业务台账的替代主源 |
| 派生分析 | `11_AI_PMO中心/`、`outputs/agents/`、周报和决策简报 | 按数据日期展示指标、发现与建议 | 待核实或待审批的分析材料，不自动改变源台账和项目基线 |
| 历史归档 | 各 `_archive/` | 追溯旧版本 | 不参与当前运行输入，除非专项任务明确指定 |

全量同步、成本同步、Agent 和决策简报现在通过 `config/current_workbooks.json` 选择业务源文件及 AI PMO 目标文件，不再按文件修改时间自动选取。登记是文件版本控制，不等于业务审批；更新登记前仍须由负责人核对审批状态、数据日期和文件内容。登记路径必须位于对应业务目录、符合文件名前缀、不是归档且文件存在，否则停止。数据质量检查还会扫描各模块目录中的工作簿结构，未登记的并列文件可能被报告为结构问题，但不参与核心业务指标计算。

## 冲突处理与发布门禁

1. 当台账、数据库和报告数值冲突时，记录对象 ID、来源文件、Sheet、源行、数据日期及运行 ID；先核对当前业务台账与人工审批证据，再查配置、转换规则和运行日志。
2. 错在源台账时由责任人修正源记录；错在映射或程序时修改规则并回归验证。不得直接改派生报告掩盖差异，也不得用旧报告反向覆盖源台账。
3. 重新运行前确认目标是否已有人工批注、结论或外发版本；必要时保留可追溯副本。`--replace-generated` 只表示明确允许替换同名派生输出，不会自动保留其中人工改动；全量原位同步虽会备份原文件，但不会自动合并任意人工改动。
4. 正式周报、风险结论、预算基线、采购选型与项目状态对外发布前，须由授权人确认数据截止日、重点差异、待决策事项和证据链接。
