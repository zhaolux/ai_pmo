# 旧合同系统来源与数据盘点问卷

状态：会前工作底稿　　适用门禁：G15（计划 2026-10-13）

## 用途与填写位置

本问卷用于访谈和收集证据，**不另建一份数据台账**。经核实的系统名称、责任人、数量和范围只填入 `09_上线移交与运营/旧合同系统迁移管理-20260920-V1.xlsx` 的“来源系统盘点”；对象级范围填“对象范围盘点”。来源描述引用既有 `上线移交与运营-20260918-V5.xlsx` 的“数据迁移与核验”MIG-001—006，仅作线索。斜杠分隔的名称可能是多个系统、模块或数据位置，不代表已确认的系统数量。

由产品经理组织业务、源系统、财务、档案、法务和技术责任人回答；项目经理核对缺口并将待决策事项带入 G15。没有核实的数据写“待盘点”，不得填 0。回答时记录证据名称、版本、生成日期、提供人与受限存放位置，不在本仓库放未脱敏合同、个人信息、账号或完整数据导出。

## 一、逐来源系统访谈问题

每发现一个独立系统或数据库，先确认是否与现有线索重复，再在“来源系统盘点”增加或拆分一行，并保留原 MIG ID 关联。

| 主题 | 必问问题 | 建议证据 | 对应填写栏 |
| --- | --- | --- | --- |
| 系统边界 | 系统正式名称、简称、环境、数据库/文件库是什么？与其他线索是同一实例、上下游接口还是独立系统？谁负责运行与数据解释？ | 系统清单、架构图、系统负责人确认 | 实际系统/库名称、是否独立系统、数据责任人 |
| 数据对象 | 存在哪些合同主数据、相对方、履约/收付款、附件、审批、签署、组织权限和 BI 初始数据？主键和关联键是什么？ | 数据字典、表/文件清单、样例结构（脱敏） | 关联对象、证据/确认人；详细字段进入“字段映射” |
| 数据规模 | 各对象记录数、合同数、附件数与容量是多少？按在办、有效、终止/到期、归档分布如何？统计时点和过滤条件是什么？ | 可复现统计脚本或查询口径、脱敏汇总结果 | 合同/记录量、附件量；对象规模进入“对象范围盘点” |
| 数据质量 | 空值、重复、失联附件、金额/状态不一致、无效账号等问题各有多少？问题是否会阻断迁移？ | 质量剖析报告、异常样本 ID（脱敏）、问题清单 | 证据/确认人；规则进入“对账与验收规则” |
| 抽取与增量 | 能否导出全量？有无可靠的更新时间、事务号或变更日志？是否支持按批次重复抽取、失败重跑和断点续传？ | 接口/导出说明、作业日志、增量字段验证 | 抽取方式；方案进入“迁移策略” |
| 安全与保留 | 谁可访问原始合同和附件？加密、脱敏、审计及跨环境传输要求是什么？旧系统停用后法定/业务查询如何保留？ | 权限矩阵、保留制度、审计与传输方案 | 历史保留边界；审批意见进入“迁移策略” |
| 运行约束 | 业务高峰、停写时长、批量导出限速、夜间窗口和备份恢复能力是什么？ | 运维窗口、备份策略、演练结果 | 抽取方式、证据/确认人；门禁进入“门禁与演练” |

数量必须附“口径 + 统计时点 + 生成方法”。例如，合同主表记录数不等同于独立合同数；附件文件数不等同于有附件的合同数。不同系统如有重复合同，应说明去重键与主源归属，不能直接相加。

## 二、现有六条访谈线索

| 线索 | 既有台账来源描述 | 优先核实的问题 |
| --- | --- | --- |
| SRC-01 / MIG-001 | 现有合同系统/档案 | 合同业务库与档案库是否独立；在办合同和历史归档合同分别归谁管理？ |
| SRC-02 / MIG-002 | 主数据平台 | 相对方主数据的权威系统、统一编码和合同系统本地副本如何区分？ |
| SRC-03 / MIG-003 | 现有业务/财务系统 | 履约与收付款是否分属系统；账务余额的核对责任和时点是什么？ |
| SRC-04 / MIG-004 | 档案/文件系统 | 正文、附件、审批和签署证据存放在哪里，如何保持主合同关联和可读性？ |
| SRC-05 / MIG-005 | 组织/身份平台 | 组织、用户、岗位、角色和数据权限的权威来源分别是什么？ |
| SRC-06 / MIG-006 | 合同系统/BI | BI 是明细来源还是派生汇总；指标口径与权限如何验证？ |

这些是六条**台账线索**，不是六套已确认的系统。发现一个线索对应多套系统时拆分记录；发现不同线索指向同一系统时建立交叉引用，不重复计数。

## 三、历史合同范围决策问题

业务负责人须按“在办、有效、终止/到期、归档”分别回答：

1. 哪些合同必须在新系统继续办理，哪些只需检索，哪些允许只读归档？判断依据是什么？
2. 合同正文、补充协议、审批轨迹、电子签署证据、附件和履约/收付款是否需要完整关联？存在缺失时谁批准例外？
3. 历史年限、档案/法务保留期限及旧系统可查询期限是什么？是否有诉讼、审计或监管冻结对象？
4. 迁移后哪些字段和文件需要逐笔核对，哪些可以抽样？金额、状态和附件证据的差异阈值由谁签收？

决策输出进入“对象范围盘点”的“批准处置”，并在 G15 纪要记录批准人和证据。未批准前，“建议处置”不能当成正式范围。

## 四、回收与质量检查

| 检查点 | 完成判定 | 未完成时的处理 |
| --- | --- | --- |
| 来源唯一性 | 每个实际系统/库有唯一名称、边界、责任人；重复线索已合并或交叉引用 | 标“待盘点”，不得公布系统总数 |
| 规模可复核 | 记录数/文件数附统计时点、过滤口径和生成方法 | 保持数量空白，不填 0 |
| 范围可决策 | 历史合同分类、建议处置、留存依据与业务责任人完整 | 带入 G15 未决事项，不默认全部迁入 |
| 技术可行 | 全量、增量、重跑、停写、备份与恢复有可验证方案 | 标识试验任务和风险，不承诺切换时长 |
| 验收可签收 | 对账维度、阈值、差异处置和签收人明确 | RDY-005 不能视为就绪 |

会前回收由产品经理汇总，技术经理复核系统与抽取条件，业务负责人确认范围，项目经理在 G15 评审稿中更新未决清单。G15 是否通过仍由授权人决定；本问卷不自动修改门禁状态或总控计划。
