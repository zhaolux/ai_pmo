## 2. 演练前进入检查

主持人逐项确认并记录证据位置。任一关键项缺失时，仅允许开展明确标记为“验证准备”的非破坏性步骤；不得宣布端到端演练通过。

1. G15 对迁移对象、历史合同范围、来源系统、责任人、数据质量规则和对账阈值完成评审；未批准时记录差项与临时验证边界，不视为正式执行授权。当前来源系统数量、数据量、历史范围和实名责任人均待盘点。
2. 在“旧合同系统迁移管理”工作簿的“来源系统盘点”“对象范围盘点”“字段映射”明确源系统、数据所有人、筛选条件、主键和跨对象关联；MIG-001—006 只是六条来源描述线索，不等于六套系统。
3. 确认测试环境与数据脱敏/访问控制、源数据快照时间、批次编号、抽取与装载脚本版本、配置和校验值，确保一次演练可追溯且可重复。
4. 确认源端与目标端独立统计口径，包含总记录数、关键状态/金额、关联对象数、附件数量及完整性；在“对账与验收规则”和质量台账约定精度、允许差异与审批人。不得把空白结果视为零差异。
5. 备份与恢复路径由技术经理验证，至少有可读取备份、抽样恢复记录和权限检查；CUT-003 是生产切换前备份任务，演练须单独保留自己的备份证据。
6. 明确谁发布停写/解冻指令、增量截点和补数方式、业务连续性人工处理及补录责任、异常升级联系人。实际窗口和耗时阈值待责任人确认，不能照搬生产日期。

## 3. 演练执行顺序与留痕

每一步记录开始/结束时间、批次编号、执行人、脚本/配置版本、源快照标识、输入输出数量、日志位置、异常编号和复核人。演练用数据不得直接覆盖生产。

| 步骤 | 操作与停/走检查 | 主要证据 |
| --- | --- | --- |
| E01 启动 | 主持人核对范围、入口检查、人员到位和演练环境；冻结本次脚本版本与样本集 | 签到/授权、范围快照、版本与环境记录 |
| E02 源端固化 | 按已确认的系统与对象截取源端快照/增量水位；独立计算控制总数 | 源快照、截点、源端控制报表 |
| E03 抽取转换 | 按映射规则运行抽取与转换；拒绝项单独编号，不静默丢弃 | 批次日志、字段映射版本、拒绝清单 |
| E04 装载关联 | 先装载主数据及合同主记录，再处理履约/审批/附件等依赖对象；顺序以经批准的依赖清单为准 | 目标装载日志、主外键/关联检查 |
| E05 独立对账 | 由质量/业务复核人员使用独立源端控制数核查数量、金额、状态、关联、附件与权限；差异逐条登记 | 质量台账结果、对账报表、差异编号与证据 |
| E06 异常处置 | 对可修复差异先定位源、规则、脚本或目标原因；保留原批次，修复后重跑受影响对象并复核，不以人工改数掩盖差异 | 缺陷/问题记录、修复审批、复测与二次对账 |
| E07 回退演练 | 注入经批准的失败场景，执行停止、隔离、恢复和源目标复核；确认无双写及漏补录 | 回退决定、恢复日志、交易/附件/权限抽查、业务确认 |
| E08 结论 | 汇总耗时、差异、未闭问题和下一轮改进，分别提出 T087 演练结论及对 MIG/RDY 的建议 | 演练报告、问题责任和截止日、签署记录 |

## 4. 对账和质量检查单

每一项均按已批准的迁移对象和来源系统逐批核对。无对象时标记“不适用”并说明依据；缺少源端控制数时标记“无法验证”，不能写“通过”。六条 MIG 均已有质量规则覆盖，但目前质量台账中已完成且附证据的验证为 0。

- 合同主数据：总数、唯一编号、版本、合同状态、签订/生效/到期日期、金额及币种口径。
- 相对方与组织：统一标识、名称映射、组织归属、用户与数据权限范围。
- 审批与履约：审批链和结果、履约节点、付款/收款计划、累计金额与余额、合同和履约关系。
- 附件与电子档案：文件数量、关联关系、文件校验值、可打开性、访问权限；不能只核对附件记录数。
- 统计与接口：关键 BI 汇总和下游接口字段口径与迁移前控制报表比对；差异须追溯至原始对象。
- 差异处理：每项记录对象键、源值、目标值、类型、严重性、根因、处置人、复测结果及批准的例外。金额容差、抽样比例、必须全量校验的字段和例外批准权限由 G15/质量责任人确认，不在本草案中预设。

## 5. 停止、回退与恢复

触发候选：关键合同或附件缺失，金额/状态差异无法在批准窗口内解决，关联/权限错误可能导致错误交易或越权，增量水位不清导致漏数/重数，恢复备份不可用，或批准的时限/阈值被突破。演练中遇到未获批准的生产级操作，立即停止该操作并升级。

1. 现场负责人暂停装载和对外开放，保留源端可用状态，不允许源目标双写；封存当前批次、脚本、日志、差异和决策时间点。
2. 技术经理评估恢复点、备份有效性及对上下游接口的影响；产品经理/业务责任人核对受影响合同和交易。按现行“回退方案”RBK-002，由项目集经理作回退决策；其他触发场景按各自 RBK 项执行。
3. 依获批方案恢复上一稳定版本或数据状态，复核合同数量、金额、状态、附件、权限及关键业务交易。恢复后的新增/停写期业务通过经批准的手工处理、补录和再对账机制处理，不能假定自动无损回放。
4. 回退后确认接口、用户访问和业务连续性，形成事件记录、根因、再切换条件及责任人；未完成恢复验证和业务确认前不宣布回退结束或重新开放。

现行 RBK-002 记载“对账结果后 30 分钟内决策”、RTO 目标 4 小时、RPO 目标 0，并标为“未演练”。这些是台账中的目标，不是已经证实可达的承诺；演练应测量实际决策、恢复及数据损失/补偿情况，再由授权人决定是否修订。

## 6. 退出与后续门禁

演练报告须明确“通过/附条件/不通过”的**建议**及依据；只有授权责任人可确认正式结果。建议通过的必要条件：所有已批准的关键对账规则有结果及可追溯证据；关键差异为零或有明确批准的例外；回退可执行且恢复验证完成；未闭缺陷有风险评估、负责人和复测日期。数值阈值仍以经批准的质量规则为准。

把演练结论反馈至迁移工作簿“门禁与演练”、质量工作簿“数据质量与迁移”、风险登记册 RSK-007 和上线工作簿对应 CUT/RBK 记录。具体业务事实只在各自权威台账录入一次；本作业方案引用记录 ID 和证据链接，不复制状态。RDY-005、MS015、CUT-001 等门禁由其授权人分别判断，演练报告不自动改变任何状态。
