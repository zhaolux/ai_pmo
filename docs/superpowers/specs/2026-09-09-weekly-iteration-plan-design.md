# AI PMO V2 周迭代计划优化设计

## 1. 目标与边界

将现有“周迭代计划”从按专业填写大段文本的计划表，升级为同时支持周度承诺复盘和设计→前端→后端→测试阶段衔接的管理视图。

本次仅优化“周迭代计划”Sheet及其必要联动，不处理“AI运行日志”自动追加。

## 2. 整体结构

采用“周度汇总 + 周任务明细”两层结构。

### 2.1 周度汇总

每个迭代周一行，字段包括：

- 迭代周
- 开始日期
- 结束日期
- 周目标
- 原周计划摘要
- 计划完成阶段数
- 实际完成阶段数
- 承诺完成率
- 延期数
- 暂停数
- 周状态
- 复盘结论

“周目标”和“复盘结论”为黄色人工输入项；其余统计优先自动生成。原表功能设计、前端开发、后端开发、功能测试文本合并为“原周计划摘要”，不丢失历史计划依据。

### 2.2 周任务明细

每个总控任务的专业阶段一行，字段包括：

- 迭代周
- 任务ID
- 任务名称
- 批次
- 专业阶段（业务/前端/后端/测试）
- 负责人
- 计划开始
- 计划完成
- 阶段状态
- 总体状态
- 实际完成日期
- 是否延期
- 异常提示
- 复盘说明

明细按“迭代周→专业阶段→任务ID”排序。状态、负责人、日期等字段从“项目总控台账”联动；“复盘说明”为黄色人工输入项。

## 3. 数据流与计算口径

1. 迭代周次和起止日期继续从`inputs`目录中最新项目计划的“周迭代”Sheet读取。
2. 业务、前端、后端、测试阶段的负责人、计划日期和状态从“项目总控台账”读取。
3. 某阶段的计划完成日期落在迭代周起止日期内时，该阶段计入当周承诺。
4. “计划完成阶段数”是当周计划完成的有效专业阶段数量。
5. “实际完成阶段数”是上述承诺中阶段状态为“已完成”的数量。
6. “承诺完成率” = 实际完成阶段数 ÷ 计划完成阶段数。当周没有承诺时显示“无计划任务”，不显示0%。
7. 已结束历史周显示实际结果；当前周显示进行情况；未来周显示计划数，不提前评价完成率。
8. 已完成状态优先结合总控台账的实际完成日期。已完成但无实际完成日期时，状态仍计为完成，同时标记“完成日期待补充”，避免低估完成率。

## 4. 异常处理

- 缺少阶段负责人：不阻断生成，标记“负责人待补充”。
- 缺少阶段计划完成日期：不归入任何周次，不计入完成率，放入“待排期”异常组。
- 计划开始晚于计划完成：标记“日期异常”。
- 总体状态为暂停或挂起：阶段明细黄色突出，计入当周暂停数。
- 历史周未完成承诺：标记延期，计入当周延期数。
- 原周计划文本无法匹配总控任务ID时：保留在“原周计划摘要”，不伪造任务映射。

## 5. 呈现规则

- 周度汇总和周任务明细均使用蓝色表头和完整框线。
- 当前周使用浅蓝底色，历史周和未来周显示明确周状态。
- 承诺完成率使用数据条；正常绿色，存在延期或暂停黄色，严重偏差红色。
- 周任务明细表头冻结，并保留筛选。
- 任务名称、原周计划摘要、复盘说明自动换行。
- “周目标”“复盘结论”“复盘说明”使用黄色输入底色。

## 6. 刷新与历史保留

每次更新V2模板时：

1. 根据迭代周次保留已填写的周目标和周复盘结论。
2. 根据“迭代周 + 任务ID + 专业阶段”保留任务级复盘说明。
3. 根据最新总控台账重建状态、负责人、日期、异常和汇总统计。
4. 新增周次或任务时扩展表格；删除的计划项不再出现，但不删除其他Sheet数据。

## 7. 验收标准

- 周度汇总的计划数、完成数、延期数和暂停数可与明细逐周勾稽。
- 承诺完成率分母不包含缺失计划完成日期的阶段。
- 总控负责人、阶段状态或日期变化后，重新更新V2模板能正确反映到周迭代明细。
- 周目标和复盘内容在更新后保留。
- 不存在`#REF!`、`#DIV/0!`、无效日期或错位引用。
- 所有表格保持完整框线，标题、表头、输入项和状态样式可清晰区分。
- 输出文件仍按运行当天日期命名。
